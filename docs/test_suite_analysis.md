## 不可变更的约束

1. **Hash 强制校验。** `N#HHHH` 锚点是从行内容+相邻行计算出的安全校验。错误的 hash 永远被拒绝，这是底线。
2. **Edit 使用代码 fence。** ````edit:path```` 是一个独立的 Markdown fenced block，不能嵌入 ````python```` 内部。这是正确的协议。
3. **`final_answer()` 不需要单独调用。** 允许模型在同一 ````python```` 块中调用 `final_answer()` 和其他工具，不需要强制分步。
4. **系统提示词中保留 `<your_file_path>` 作为通用占位符。** 不替换为具体任务路径，保持通用性。

## 已实施的改进

### E010 — SyntaxError（从 48.8% → 5.0%）

**根因：** 模型混淆 fence 类型，把 `edit:` 或 `file:` 写在 ````python```` 块内；或用工具名（````read_file````）作为 fence 语言。

**改进措施：**
1. 系统提示词中添加反面示例（"Do NOT use tool names as fence types"）
2. `parse_step()` 中添加 fence 归一化正则，自动修正 ````python\nedit:path```` → ````edit:path````
3. `parse_step()` 中添加 ````read_file(...)```` → ````python\nread_file(...)```` 归一化
4. E010 恢复提示精简到 3 行核心模式

### E012 — final_answer 与工具混用（完全消除）

**根因：** 协议要求 `final_answer()` 单独调用，但模型想"验证并完成"一步到位。

**改进措施：** 移除 E012 检测逻辑，允许 `final_answer()` 与其他工具在同一块中调用。这是合理的——如果验证失败，E003 仍然会阻止。

### E013 — 无效路径（完全消除）

**根因：** 模型直接复制 `<your_file_path>` 占位符。

**改进措施：**
1. E013 恢复提示更明确地指出复制了占位符
2. `write_blocks()` 中自动检测 `<your_file_path>` 并从其他块或 `written_path` 中找真实路径替换

### E009 — 锚点失效（从 27.5% → 21.2%）

**根因：** 文件修改后 hash 失效，模型继续用旧 hash。9B 模型注意力有限，不会仔细读取注入的全文。

**改进措施：**
1. 系统提示词增加 hash 失效机制说明（编辑后相邻行 hash 也会变）
2. E009 恢复消息直接给出正确 hash（从 `[E_STALE_ANCHOR]` 错误中提取 `now N#CORRECT`），而不是注入整个文件内容
3. E009 恢复后重置 read_only_counter，避免误触 read-only guard

### E001 — 无代码块（从 21.2% → 18.8%）

**根因：** 模型只输出分析文本或只调用 `read_file()` 而不编辑文件。

**改进措施：**
1. E001 恢复提示加入"必须编辑文件，不仅仅是读取"的引导
2. 添加 read-only loop guard：连续 3 步只调 `read_file` 不编辑时，强制推送编辑指令
3. 添加无代码块计数器：连续 3 次纯文本输出时强制输出模板

### E007 — 循环（从 3.8% → 1.2%）

**改进措施：** E007 恢复提示建议使用 ````file:```` 全量重写绕过 hash 问题。
